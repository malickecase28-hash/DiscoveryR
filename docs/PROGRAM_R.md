# Program R — Market Research

Program R answers what information exists, what predicts what, under which conditions, and how stable the observation is. It produces evidence and knowledge records; it does not create trading authority.

The declared reusable flow is:

`Detector Atlas → anchor program → native phenotype → question generation → same-domain/cross-domain discovery → candidate → method challenge → detector confirmation → characterization → instrument report → knowledge graph/store`.

The Atlas dispatches by detector roles. Lifecycle/object templates cover formation, persistence, transition, termination, censoring, and prospective behavior. State/regime templates cover occupancy, transition, duration, and persistence. Event templates cover incidence, clustering, magnitude, recurrence, and prospective consequence. Quality templates cover failure modes, incidence, persistence, and contamination implications. Normalization/context templates cover distribution, stability, regime interpretation, and lawful causal usage.

Every stage consumes a frozen scope and causal availability clock. Occurrence time remains provenance. Completed lifecycle state cannot filter an earlier cohort. Native scale and lineage are retained, and derived detectors do not count as independent confluence.

## Population is the scientific unit

An experiment is a population of anchor instances, not one timestamp. The canonical generic runner accepts anchor instances across the frozen interval and checks context availability separately for each anchor. Missing context does **not** remove an anchor from the population; it remains explicit missingness in the result denominator. Anchor and context native scales are represented separately so E3 does not require pretending tick, 15s, 4h, or other scales are one statistical population.

Phenotype-only E1 work requires no context metric. When generic context metrics are used, candidate promotion is impossible without a predeclared support/effect gate.

## Question generation and execution are separate

Question generation is blind to prior winners. It accepts frozen phenotype/ontology/lineage/permissions and semantically compatible operators. It does not get outcome winners merely to decide which question to ask.

The generic population runner intentionally implements only a few semantics-neutral numeric kernels:

- `context` → Pearson numeric association;
- `directional` → sign-concordance fraction;
- `temporal` / `lead_lag` → mean lawful availability lag.

It rejects attempts to label those kernels as `nesting`, `spatial`, `state_transition`, `lifecycle`, `regime`, `interaction`, or `incremental_information`. Those relationships require typed detector/role-specific adapters and an experiment contract that defines the relevant observation and outcome. This prevents a universal correlation function from masquerading as detector science.

Discovery preserves negative, conditional, null, contradictory, partial, and inconclusive evidence. Statistics are synthetic-tested reusable operations; this document defines no scientific threshold or result.

## Confirmation boundary

R confirmation freezes its claim and method contract before a separately authorized process consumes held-out data. A research worker cannot unlock confirmation. The worker-facing CLI remains activation-locked; authority-bearing confirmation requires an externally signed custodian artifact plus an authority-eligible challenged stage report.

High-volume detector scans remain streaming Rust adapter/scanner work. The generic population runner consumes bounded typed observations/results; it is not a replacement for 68M-row detector-specific scanners.
